# intent-and-architecture

## Исследование спроса и архитектура

Не ограничивайся сбором ключей. Строй карту задач: что человек пытается выбрать, узнать, рассчитать, проверить, сравнить или заказать; какая информация нужна до решения; какие условия способны изменить выбор.

Источники спроса: реальные запросы сайта, внутренний поиск, вопросы продаж и поддержки, доступная аналитика, документация продукта, актуальная выдача по целевому рынку и цитируемые источники. Обезличивай клиентские данные и не отправляй закрытые сведения внешним моделям без разрешения.

Для каждого кластера укажи:

- намерение и задачу пользователя;
- реальную услугу/товар/экспертизу, с которыми он связан;
- регион, язык, этап решения и коммерческую ценность;
- текущую посадочную и факт её соответствия;
- тип нужного материала, конкурирующие форматы и недостатки существующего ответа;
- подтверждённость спроса и уровень уверенности;
- индексируемый URL либо обоснование, почему достаточно раздела существующей страницы;
- необходимую информацию, её источники и отсутствующие доказательства;
- критерий успеха и риск привлечения неподходящей аудитории.

Изучай состав SERP по выборке запросов: локальный блок, каталоги, магазины, обзоры, видео, ответы ИИ, бренды и официальные материалы. Не делай постоянных выводов по одной выдаче и не копируй конкурента целиком. Частотности и сложности из разных сервисов не являются абсолютными величинами.

Предпочитай страницу, полноценно решающую задачу, набору страниц под перестановки слов. Query fan-out используй как способ выявить реальные связанные потребности, а не разрешение генерировать отдельную страницу под каждый предполагаемый подзапрос.

Для каннибализации исследуй смену целевых URL по запросам, совпадение намерений, периоды, устройства, локали, конверсии и внутренние ссылки. Несколько URL по запросу сами по себе не доказывают проблему. Выбор действия: различить назначение страниц, улучшить основную, скорректировать ссылки, объединить эквивалентные материалы с релевантным редиректом или оставить всё как есть.

При выборе `keep / improve / merge / redirect / noindex / remove` учитывай полезность, точность, сезонность, спрос, ссылки, историю, коммерческие функции и затраты поддержки. Не удаляй страницу только за нулевой трафик за короткий период. Не переписывай URL ради включения ключа, если выгода не оправдывает миграционный риск.

Внутренние ссылки проектируй как путь решения: обзор → услуга → условия → доказательства → действие. Используй обычные доступные ссылки, описательные анкоры и связь по смыслу. Анализ графа, центральность и глубина — диагностические инструменты; не заявляй, что твой расчёт воспроизводит PageRank Google. Не создавай глобальные блоки из сотен однотипных ссылок.
