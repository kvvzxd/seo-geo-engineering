# Контракты инструментов

Все примеры `example.com` и цены в assets — синтетические фикстуры. Никогда не переносить их на сайт клиента. Команды работают с локальными данными, Python 3.10+, без сторонних библиотек. JSON — фактически поддерживаемый формат; YAML допустим для проекта только после отдельной проверенной конвертации. Общая опция `--out` идёт **перед** подкомандой.

## Политика доступа

В режиме managed_block генератор сохраняет неуправляемый текст и материализует прежние fallback-правила `*` при добавлении специфичной группы, чтобы она случайно не открыла ранее закрытые пути. Это не полное доказательство эквивалентности произвольных политик: явные новые Allow/Disallow и перекрывающиеся правила требуют осмотра diff и матрицы. Поле `access_changes` показывает до/после для критических URL; добавляй примеры важных исключённых путей, ресурсов рендера и граничных случаев.

```text
python <skill>/scripts/seo_geo.py validate policy.json
python <skill>/scripts/seo_geo.py --out plan.json plan policy.json --root <public-root>
python <skill>/scripts/seo_geo.py apply plan.json --environment production
python <skill>/scripts/seo_geo.py verify plan.json
python <skill>/scripts/seo_geo.py drift plan.json
python <skill>/scripts/seo_geo.py rollback plan.json --environment production
```

`<public-root>` должен существовать. Вход: [policy.example.json](../assets/policy.example.json), формальная [схема](../assets/policy.schema.json). `ownership: managed_block` сохраняет неуправляемое содержимое; `whole_file` означает явно заданную полную переработку robots. Группы и правила перечисляются явно, роли обучения и поискового доступа не меняются по догадке. Генератор поддерживает только Allow/Disallow/Sitemap. Clean-param и прочие расширения подготавливает агент по профильной документации, не этот генератор.

Критические URL проверяются ограниченным профилем Google. `token` — точный токен робота для анализа, не доказательство реального запроса от него. Для других движков сохраняй `unknown` и используй подходящие проверенные инструменты; не называй локальную симуляцию подтверждением их поведения. Разбор robots намеренно консервативен: диагностики непонятных строк, слишком большого файла и неизвестных директив приводят к unknown, даже если конкретный реальный робот их проигнорирует.

В матрице можно задать `expected_indexing` вместе с фактическим `capture`. Это проверка сохранённого ответа, не свежая проверка рабочей среды. Собери новый снимок после публикации и выполни `inspect`. `verify/drift` сравнивают локальные файлы с подготовленными хэшами; периодический запуск по расписанию не создаётся автоматически.

Опциональный `llms.enabled: true` требует `use_case`, `description` и `links` из публичных материалов своего origin. Достоверность описания и отсутствие закрытых URL/инъекций проверяет агент до применения. Генератор не решает это по ключевым словам. Для `llms.txt` при включении используется полное управление файлом; существующая версия включается в diff и резервную копию.

План содержит исходное и предлагаемое содержимое и хэши, поэтому держи его локально и проверяй перед исполнением. Контрольная сумма защищает от случайного изменения, не аутентифицирует автора плана. Из недоверенного источника план не исполнять. Права команды `apply` равны правам пользователя процесса.

Запись атомарна для одного файла. Lock сериализует экземпляры этого инструмента; проверка хэша до записи обнаруживает существующие конкурентные правки. Между последней проверкой и заменой файла возможна гонка с внешним редактором: это не транзакция файловой системы или внешнего CMS. Для рабочей среды используй версии/ETag/транзакцию её адаптера. Компенсация завершённых записей выполняется только если файл остался в записанном инструментом состоянии. После сбоя проверь все файлы; не удаляй lock без выяснения состояния процесса.

Ни robots, ни lock не служат защитой приватных данных. Среды production/staging сверяются при apply/rollback; сам CLI не знает, на каком хостинге опубликована папка. Не запускать apply против произвольной папки без привязки к разрешённой задаче.

## Снимки и факты

```text
python <skill>/scripts/seo_geo.py inspect capture.json
python <skill>/scripts/seo_geo.py facts facts.json capture.json
python <skill>/scripts/seo_geo.py compare before.json after.json
```

Снимок содержит URL, captured_at, capture_method, status, headers и html. Повторяющиеся HTTP-заголовки передавай массивом строк. Время и метод сбора должны отражать реальность. `inspect` анализирует статический HTML; не определяет CSS-видимость, выполнение JS, фактический основной контент или попадание в индекс. Текст может содержать скрытые стилями элементы. Browser/DOM и мобильную проверку выполняет агент доступными инструментами.

Для PDF можно передать заголовки и пустой html; полноценное извлечение PDF выполняется внешним инструментом. Canonical в HTTP Link и все возможности произвольных заголовков этот парсер не моделирует. Сложные scoped-директивы, неизвестная семантика или некорректный HTML требуют отдельной проверки. Результат `no_blocking_directive` означает только, что реализованный анализ не нашёл известный noindex; не подтверждает eligibility.

В [реестре](../assets/facts.example.json) `checks.scope_regex` задаёт **проверенный агентом** фрагмент конкретной сущности. Шаблоны — доверенный локальный ввод: не исполнять шаблон с чужой страницы. Ограничивай выражения и область текста; не используйте сложные вложенные квантификаторы. Сопоставление required_text буквальное и может требовать корректировки при допустимом форматировании цены. Формальная [схема](../assets/facts.schema.json) описывает структуру.

Результат `checks_satisfied` не доказывает истинность или семантическую эквивалентность. Обязательно проверить отношения услуги, единицы, валюты, условий, региона, периода и источника вручную/агентом с доказательствами. Без scope результат помечается; неизвестный статус тоже. JSON-LD и другие версии сравниваются семантически отдельно. Пустой список фактов не является разрешением на публикацию; проверять полноту реестра.

## Поисковые CSV

```text
python <skill>/scripts/seo_geo.py analytics export.csv --context context.json
```

Нормализованный CSV: `date,page,query,clicks,impressions` и опционально `position`; дата ISO. Контекст: engine,property,search_type,country,device,timezone. Дополнительные контекстные колонки проверяются, если присутствуют. Данные из несовместимых свойств/систем нормализуй раздельно. CLI не восстанавливает анонимизированные запросы и строки за пределами экспорта, не выводит причинность или фиксированную позицию. Средняя позиция взвешена показами.

## Панель генеративного поиска

```text
python <skill>/scripts/seo_geo.py geo observations.json --domain example.com --brand "Example Brand"
```

`observations.json`: объект с массивом `runs`. Для каждого запуска обязательны уникальный run_id, query_id, query, engine, surface, language, country, timestamp, collection_method, answer. Дополнительно cited_urls и fact_checks с результатом correct/incorrect/unknown. Сохраняй модель, режим поиска, персонализацию, версию конфигурации и клиента в реальных данных; не смешивай разные условия в одном наборе, если они не отражены отдельным surface/collection_method.

Поля `model`, `configuration_version`, `search_or_browsing_enabled`, `personalization_state`, `device_or_client` дополнительно разделяют группы. Отсутствующее значение явно называется unknown. `branded_query_runs` показывает, сколько запросов уже содержали бренд; панель только из таких вопросов не доказывает небрендовую видимость.

CLI считает присутствие ссылки, упоминания бренда, условную цитируемость и долю предоставленных ошибочных аннотаций. Unknown выводится отдельно. Совпадение поддомена учитывается, похожий чужой домен — нет. Упоминание не означает рекомендацию; аннотации достоверности поступают из отдельной проверки. Пустой ответ и отсутствие источников отличаются от пропущенного ответа. Есть число уникальных запросов и повторов; нет псевдоточного CI по зависимым наблюдениям. API-набор не представляется пользовательским UI.

## Коды завершения

0 — операция/реализованная проверка выполнена; 2 — ошибка, несоответствие, регрессия или flagged-факт. Всегда читать JSON, ограничения и семантические замечания. Нулевой код не доказывает готовность к публикации и эффективность SEO.
